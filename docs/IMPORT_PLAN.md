# План: импорт выписок с памятью

Статус: реализована версия для ручного тестирования; автоматические проверки и сборка APK прошли. Приёмка владельцем впереди.
Итоговую архитектурную документацию обновляем после ручного тестирования.

## Поведение

- Повторная выписка добавляет новые операции и сохраняет прошлые исправления.
- Исходные данные сопоставления не меняются при редактировании покупки.
- Без банковского идентификатора совпадение считается возможным повтором: пользователь может добавить его как отдельную покупку.
- Одинаковые покупки учитываются по количеству, а не схлопываются в одну.
- Новые места можно уточнить до сохранения или позже в списке операций.
- Правка одной покупки и запоминание магазина — отдельные действия.
- Правила и знакомое название магазина сохраняются только при подтверждении импорта.
- Непроверенные автоматические категории не используются как обучающие примеры.
- История показывает результаты загрузок и позволяет отменить добавленные операции с подтверждением.

## Этапы

1. Регрессионные тесты повторного импорта, правок, одинаковых покупок и валют.
2. Исходный ключ операции, отдельное описание из выписки, миграция Room без потери данных.
3. Сопоставление с существующими покупками, защита от повторного сохранения.
4. Память магазинов: исходное название → знакомое название → категория; групповое применение.
5. Список требующих проверки, ручное редактирование после импорта, обучение на подтверждениях.
6. Атомарное сохранение истории, операций и правил; просмотр и отмена импорта.
7. Unit-тесты, сборка APK, самопроверка по `/review-pr`.
8. Ручная проверка владельцем; затем итоговая документация.

## Ручная проверка

- Импортировать выписку, исправить «ИП Сергеев» на «Арзан», выбрать категорию и запомнить магазин.
- Загрузить ту же выписку: совпавшие покупки пропущены, исправления сохранены.
- Загрузить выписку с перекрывающимся периодом: добавляются только новые покупки.
- Сохранить неизвестный магазин без уточнения; затем исправить покупку через список операций.
- Проверить две одинаковые покупки в один день и возможность явно добавить совпадение.
- Проверить отдельные обозначения счетов при импорте выписок разных карт одного банка.
- Отменить предпросмотр с правками: память магазинов не меняется.
- Открыть историю и отменить один импорт: предыдущие покупки остаются.
- Перезапустить приложение: история, правила и исходные данные сохранены.

## Ограничения

PDF не всегда содержит идентификатор операции или счёта. Для разных счетов нужно указывать разные обозначения; без идентификатора совпадения требуют возможности ручного решения. Старые исправленные описания невозможно восстановить из прежней базы автоматически. В этой версии не добавляются OCR, облачный справочник и обучение нейросети.

## Автоматическая проверка версии для тестирования

Команда: `./gradlew :shared:testAndroidHostTest :app:testDebugUnitTest :app:assembleDebug`.
Задача `:shared:testDebugUnitTest` из AGENTS.md отсутствует в текущей конфигурации KMP; используется `:shared:testAndroidHostTest`.

Проверены повторный импорт после ручных правок, количество одинаковых покупок, разделение счетов и валют, использование подтверждённой истории, миграция Room 4 → 5, отмена конкретной загрузки и полный откат при ошибке записи правила.
Два существующих теста реальных PDF пропущены: локальные файлы `kaspi.pdf` и `freedom-.pdf` отсутствуют. Ручная проверка ваших выписок остаётся обязательным этапом приёмки.

APK: `app/build/outputs/apk/debug/app-debug.apk`.
Отмена импорта сохраняет запомненные правила магазинов; об этом предупреждает диалог подтверждения.
